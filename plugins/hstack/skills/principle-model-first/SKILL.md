# Model First

**언제:** 상태가 있는 로직을 쓸 때, 조건문이 늘어날 때, 같은 데이터 형태 가정이 여러 파일에 반복될 때.

**규칙:** 도메인을 흩어진 조건문이 아니라 구조에 담는다. 좋은 구조는 불가능한 상태를 표현할 수 없게 만들고 분기를 지운다.

**한다**
- 서로 맞춰야 하는 boolean 여러 개나 단계 검사 → 상태 머신이나 enum.
- 느슨한 매개변수 묶음 → 타입이 있는 모델.
- 여러 파일에 퍼진 분기 → 맵, 레지스트리, 판별 유니온(discriminated union).
- 여기저기서 하는 즉석 변경 → 한 곳의 상태 전이 함수(reducer).
- 접근 패턴이 요구하면 인덱스, 큐, 정규화된 컬렉션.

**절제**
- 형태가 분명하고, 국소적이고, 커질 일이 없으면 단순한 코드를 그대로 둔다.
- 분기나 불가능한 상태를 지우지 못하는 구조는 간접층만 더한다. 넣지 않는다.
- 기존 코드가 다른 방식으로 이미 풀고 있으면 `principle-follow-the-codebase`를 먼저 본다.

**신호**
- 기능 하나를 넣으려고 if/else 사슬에 분기를 또 붙인다.
- 새 boolean을 기존 boolean과 같이 갱신해야 한다.
