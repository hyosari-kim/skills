### Runtime forensics

**진단을 소유한다. 소스로 이론을 세우지 말고 살아 있는 프로세스를 계측한다.** 결과물은 근거를 단 진단이다. 수정이 아니다.

1. control 스킬(**control-ui** 또는 **control-cli**)로 맞는 화면에서 살아 있는 신호를 잡는다. 계속 도는 프로세스면 CPU 프로파일, 누수면 힙 스냅샷, 화면 깨짐이면 CDP trace다. 추측이 아니라 실제 산출물이다.
2. 산출물을 결정적 증거로 줄인다. 핫 패스의 함수, 누수된 객체에서 GC 루트까지의 retainer 체인, 입력 없이 도는 루프. 큰 산출물은 서브에이전트에서 파싱하고(**principle-guard-the-context-window**), 줄인 결과만 메인 스레드에 둔다. 각 서브에이전트의 effort는 SKILL.md의 Subagents 섹션에 따라 일에 맞게 고른다.
3. 믿기 전에 메커니즘을 증명한다. 실행 중인 프로세스에 CDP eval로 계측을 넣거나, 다시 로드하지 않고 살아 있는 코드를 핫픽스해서 가설을 싸게 확인한다.
4. 결과를 소스로 되짚는다. 파일, 심볼, 할당하거나 스케줄하는 줄.
5. 처리량 체크포인트는 한 줄로 둔다. `throughput checkpoint: n/a, read-only forensics`.

**Reply:** 잡은 신호, 줄인 결과, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로. 요청이 없으면 수정하지 않는다. 원인이 밝혀지면 Bug fix나 Perf issue로 넘긴다.
