### Eval

**실험 설계를 소유한다. 계획하고, 블라인드하고, 돌리고, 종합한다.**

**블라인드에서 양보하지 않는 것:**

- 후보가 보는 디렉터리, 파일, 프롬프트 어디에도 `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, `arena`를 넣지 않는다.
- 후보 프롬프트는 자연스러운 사용자 요청처럼 보인다. 메타가 아니라 목표를 말한다.
- 사슬을 끌어내는 단서를 주지 않는다. 후보에게 어떤 스킬, 원칙, 파일을 적용했는지 나열하라고 하지 않는다. 설계 메모는 일반적으로 요청하고, 사슬을 따랐는지는 자기 보고가 아니라 코드 모양으로 채점한다.
- 디렉터리와 slug 이름을 정리한다. 사용자가 고를 법한 프로젝트 같은 이름을 쓴다.
- 다른 후보가 있다고 후보에게 말하지 않는다.
- 심판은 자기가 심판한다는 것을 알아도 되지만, 출력은 정리된 라벨로만 보고 모델 이름은 보지 않는다.
- 두 변형을 비교할 때는 심판 하나가 두 묶음을 한 번에 같은 척도로 채점하고, 각 묶음이 어디서 왔는지 모른다.

**단계:**

1. **틀을 정한다.** 어떤 변형을 시험하는지, 어떤 동작이 성공인지 적는다. 심판용 루브릭(구체적인 기준 3~6개)을 쓴다. 후보에게는 보여주지 않는다.
2. **정리된 환경을 만든다.** 후보마다 변형이 들어간 작업 디렉터리를 둔다. 자연스러운 작업에 있을 맥락을 심어둔다. 프로젝트 뼈대, 후보가 자연스럽게 읽을 스킬.
3. **자연스러운 프롬프트 하나를 쓴다.** 사용자가 칠 법한 것이다. 무엇을 재는지 새지 않게 한다.
4. **N개의 후보를 병렬로 띄운다.** **arena**의 Phase B에 따라 서로 다른 모델(`Agent` 도구의 `model` 값)에서 돌린다. 각자 정리된 자기 디렉터리에서 일한다. 모두 같은 프롬프트를 받는다. 각 서브에이전트의 effort는 SKILL.md의 Subagents 섹션에 따라 일에 맞게 고른다. 띄우고, 확인하고, 결과를 묶기만 하는 에이전트는 `model: "opus", effort: "medium"`으로 돌린다.
5. **블라인드 심판 하나를 띄운다.** **arena**의 Phase C에 따라 후보와 다른 모델에서 돌린다. Claude Code의 `model` 값은 모두 Claude 계열이라 다른 회사 모델 심판은 아니다. 심판은 정리된 라벨로 된 출력과 루브릭만 보고, 모델 이름은 보지 않는다.
6. **사슬은 자기 보고가 아니라 대화 기록으로 확인한다.** 각 후보의 대화 기록을 이 워크스페이스 폴더 `~/.claude/projects/<slug>/`에서 읽는다(slug는 워크스페이스 경로에서 영숫자가 아닌 글자를 모두 `-`로 바꾼 것이다). 서브에이전트 기록은 `<session>/subagents/` 아래에 있고, worktree에서 돈 후보는 그 worktree 경로의 slug 폴더에 있다. `~/.claude/projects/*/`를 통째로 glob하지 않는다. 워크스페이스 경계를 넘어 관련 없는 프로젝트의 비공개 대화를 읽게 된다. 각 후보가 실제로 연 파일을 본다. 사슬을 따랐는지는 실제로 읽은 파일과 코드 모양으로 채점하고, 후보 자신의 주장으로 채점하지 않는다.
7. **후보 출력을 전부 직접 처음부터 끝까지 읽는다.** 심판의 판정과 비교한다. 어긋나면 모델이 편향됐거나 루브릭이 모호한 것이다. 종합한다.

**Reply:** 시험한 변형, 루브릭, 후보별 메모, 심판의 판정, 내 종합, 변형을 승격할지에 대한 권고.
