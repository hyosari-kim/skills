### Session pickup

**이어갈 지점을 소유한다. 앞선 흔적을 읽는다. 다시 하지 않는다.**

1. 앞선 흔적을 찾는다. 이 워크스페이스 폴더 `~/.claude/projects/<slug>/<session>.jsonl`의 대화 기록(slug는 워크스페이스 경로에서 영숫자가 아닌 글자를 모두 `-`로 바꾼 것이다. `~/.claude/projects/*/`를 통째로 glob하지 않는다. 워크스페이스 경계를 넘어 관련 없는 프로젝트의 비공개 대화를 읽게 된다)이나 push된 브랜치다. 메타데이터 개요와 마지막 메시지를 먼저 읽고, 거슬러 올라가며 결정 지점을 훑는다. 긴 기록은 서브에이전트에서 파싱하고 줄인 타임라인만 메인 스레드에 둔다(**hyosari-principle-guard-the-context-window**). 각 서브에이전트의 effort는 SKILL.md의 Subagents 섹션에 따라 일에 맞게 고른다.
2. 작업 상태를 재구성한다. 브랜치와 worktree, 이미 들어간 것(`git log`, base 대비 `git diff`), 열린 할 일, 내려진 결정. 앞선 흔적은 권위 있는 입력이다. 다시 도출하고 싶은 충동을 참는다.
3. 끝난 것과 남은 것을 비교한다. 출하된 것을 계획한 것과 대조하고, 이어갈 지점을 이름 붙인다. 앞선 재현을 다시 돌리거나 끝난 일을 다시 하지 않는다. "처음부터 확인해 보자"는 흔적이 권위 있는데도 못 믿을 것으로 다루는 것이다.
4. 남은 일을 맞는 플레이북으로 보내고 판정을 고른다. 실행을 이어가기, 끝난 권고를 출하하기, 앞선 결론을 승인하거나 뒤집기, 실패한 실행의 사후 분석. 이 플레이북은 여기서 끝난다. 보낸 플레이북이 나머지를 소유한다.
5. 물려받은 주장을 원래 목표에 대고 실제 산출물로 검증한다(**hyosari-principle-prove-it-works**). 통과했다는 앞선 자기 보고는 증명이 아니다.
