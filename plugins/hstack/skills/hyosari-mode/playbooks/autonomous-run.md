### Autonomous run

**종료 조건을 소유한다. 끝을 정의하고, 멈추지 않고 거기까지 간다.**

1. 첫 반복 전에 종료 조건을 확인 가능한 조건식으로 적는다(테스트 통과, 재현 해결, N개 PR 모두 머지, 픽셀 diff 0).
2. Claude Code의 `/loop` 명령(내장 명령이다. hstack 스킬이 아니다)으로 깨우는 방법을 고른다. 지켜볼 이벤트(CI, 머지, ref 전진)가 있으면 그 이벤트에 나를 깨우는 감시 서브에이전트를 두고, 대비책으로 긴 시간 간격 heartbeat를 둔다. 이벤트가 없으면 결과를 다시 볼 가치가 생기는 시점에 맞춘 고정 간격 heartbeat를 둔다. 각 서브에이전트의 effort는 SKILL.md의 Subagents 섹션에 따라 일에 맞게 고른다.
3. 반복마다 증거가 정당화하는 가장 작은 변경을 하고, 조건식에 대고 검증하고, 진전했으면 커밋하고, 도움이 안 된 변경은 버린다. "도움이 될 수도 있는" 이중 안전장치는 남겨두지 않고 되돌린다.
   **principle-sequence-verifiable-units**로 작업 순서를 정하고, 확인을 끝에 몰지 않고 단위마다 검증한 뒤 다음으로 간다.
4. 목표를 돕는 도중의 발견은 내 일이다. 깨진 스킬, 관련 버그, 불안정한 검증기, 리뷰 노이즈, 도구 실패, 고아가 된 후속 작업, 고칠 수 있는 어긋남은 hyosari-mode로 직접 처리한다. 본 흐름 밖의 수정은 따로 PR을 낸다. 되돌릴 수 있는 일을 사람에게 미뤄두거나 `AskUserQuestion`을 쓰지 않는다. 되돌릴 수 없는 작업, 실험으로 정할 수 없는 진짜 제품·취향 결정, 진짜 막다른 길만 드러낸다. 조건식을 주된 동력으로 두고, 곁가지 수정마다 거기로 돌아온다.
5. 반복마다 **show-me-your-work**로 체크포인트를 남긴다. 무엇이 바뀌었고 조건식이 움직였는지 한 줄이다.
6. 조건식을 만족하면 멈춘다. 정체는 멈춤이 아니다. 계속 가고, 접근을 바꿔 넘어선다. 헛돌지 말고 진짜 막다른 길은 드러낸다. 승리를 선언하려고 조건식을 느슨하게 하지 않는다.
