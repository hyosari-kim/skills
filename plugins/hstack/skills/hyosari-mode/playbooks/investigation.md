### Investigation

**답변을 소유한다. 계획하고, 따라 읽고, 쓴다.**

읽기 전용 요청이다. 코드 변경이 아니라 근거 있는 설명이나 권고를 낸다.

1. 질문이 가리키는 코드를 따라 읽는다. 지금 어떻게 동작하는지 묻는 질문이면 **hyosari-how**를 쓴다. 왜 그렇게 만들었는지 묻는 질문이면 **hyosari-why**를 쓴다.
2. 실행하면 확인되는 것은 추측하지 않고 실행해서 확인한다.
3. 출력은 개요 / 핵심 개념 / 동작 방식 / 어디에 있나 / 주의점 순서로 쓴다. 대안 중에 고르는 질문이면 권고와 트레이드오프 표를 낸다.
4. 조사하다 코드 변경이 필요해지면 슬쩍 고치지 않는다. 멈추고 사용자에게 돌려준 뒤 Bug fix나 Feature로 다시 매칭한다.
5. 처리량 점검(throughput checkpoint)은 한 줄로 쓴다. `throughput checkpoint: n/a, read-only investigation`.
6. 답변에 **hyosari-unslop**을 적용한다.

PR을 열지 않는다. 조사가 코드 변경으로 이어지지 않으면 **hyosari-architect**도 쓰지 않는다. 이어지면 4번대로 사용자에게 돌려준다.

**Reply:** 조사 결과 그대로. "확실해?" 같은 질문에는 진짜 판단과 이유를 쓴다. 질문의 전제가 틀렸으면 반박한다. 반박은 SKILL.md의 Autonomy를 따른다.
