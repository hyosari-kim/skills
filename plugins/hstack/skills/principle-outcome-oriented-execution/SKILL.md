# Outcome-Oriented Execution

매끄러운 중간 상태를 지키기보다 의도한, 확인할 수 있는 최종 상태를 위해 최적화한다.

**이유:** 모든 중간 단계를 완전히 안정되게 유지하려다 보면 임시 호환 코드가 생기고, 그것이 오래 남는 빚이 된다. 목표 아키텍처로 수렴하고, 명시한 확인 경계에서 올바름을 증명한다.

**핵심 규칙:**
- 전환기의 안정성보다 최종 상태의 온전함을 앞세운다.
- 중간에 깨지는 것은 계획되고, 범위가 정해지고, 되돌릴 수 있으면 받아들인다.

**울타리:**
- 단계 경계가 명시된 계획된 재작성과 마이그레이션에 쓴다.
- 임시로 깨져도 되는 곳을 밝힌다.
- 마이그레이션하는 동안 지금 손대는 영역에는 신호가 강한 확인을 유지한다.
- 계획이 끝나면 정적 확인과 런타임 확인을 모두 요구한다.
