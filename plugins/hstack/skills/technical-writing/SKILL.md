# Technical writing

지친 엔지니어가 한 번 읽고 이해하도록 쓴다.

- 일하지 않는 단어는 모두 지운다.
- 짧고 일상적인 단어를 쓴다. "utilize"가 아니라 "use".
- 규칙을 따랐더니 문장이 나빠지면 다른 방법으로 고치거나 그대로 둔다.
- 동의어나 설명이 아니라 실제 심볼, 파일, 플래그, 명령 이름을 쓴다.
- 용어를 지어내지 않는다. 개발자가 소리 내어 말할 단어를 쓴다. 이름 붙은 패턴은 처음 나올 때 뜻을 말한다.

## 리듬을 바꾼다

- 문장 길이를 섞는다. 생각 둘을 실은 문장은 나눈다. 생각 하나를 실은 긴 문장은 둔다.
- 설명 문서에서는 관점을 가진다. 레퍼런스는 건조하게 둔다.
- 구체적으로 쓴다. "schema changes can cause issues"가 아니라 "a column rename fails the build".

## 먼저 모드를 고른다 (Diátaxis)

문서 하나에 모드 하나. 모드를 섞지 않는다. 대신 나누고 링크한다.

- **Tutorial. 해 보며 배운다.** 학습자가 무엇을 만들지 말한다. 모든 단계가 눈에 보이는 결과를 내고, 무엇이 보여야 하는지 말한다. 설명은 한 구절과 링크로 끝낸다.
- **How-to. 목표까지의 단계.** 독자의 문제를 푼다. 독자의 역량을 가정한다. 행동만 쓴다. 갈림길을 허용한다. 가이드 이름은 작업으로 짓는다.
- **Reference. 찾아보는 사실.** 설명만 한다. 건조하고, 빠짐없고, 확신 있게 쓴다. 설명하는 대상의 구조를 그대로 따른다.
- **Explanation. 이해와 이유.** 경계가 있는 주제 하나. 맥락을 준다. 설계 결정, 역사, 제약, 대안. 의견은 여기서만 허용한다.

## 독자에게 문장을 쓴다 (Google developer style)

- 독자를 "you"로 부르고 현재 시제로 쓴다.
- 누가 무엇을 하는지 말한다. 수동태는 행위자를 모르거나 요점과 무관할 때만 쓴다.
- 지시는 명령문으로 쓴다. 조건을 지시 앞에 두고, 흔한 경우를 먼저 쓴다.
- 유행어, 비유, "please"를 쓰지 않고, 절차에서는 "simply", "easy", "quickly"를 절대 쓰지 않는다.
- 미리 예고하지 않고, 연이은 문장을 같은 구절로 시작하지 않는다.
- 링크는 어디로 가는지 말하는 단어로 건다.
- 제목은 요점을 담고 sentence case로 쓴다. 페이지마다 h1은 하나, 수준을 건너뛰지 않는다.
- 순서에는 번호 목록, 나머지는 글머리표를 쓴다. 목록은 완전한 문장으로 소개한다. 항목은 나란한 형태로 맞춘다.
- 코드는 코드 글꼴, UI 요소는 굵게 쓴다. serial comma를 쓴다. "etc."는 뺀다.

## 진술을 하나씩 싣는다 (STE 규칙)

- 문장 하나에 지시 하나. 그 밖에는 문장 하나에 생각 하나.
- 지시는 약 20단어, 다른 문장은 약 25단어가 넘으면 나눈다.
- 경고나 조건은 그것이 지키는 단계 앞에 둔다.
- "the"와 "a"를 남긴다.
- 단어 하나에는 뜻 하나를 주고, 행동 하나에는 단어 하나를 고른다.
- 절차는 직접 명령으로 쓴다. 서술이나 수동태로 쓰지 않는다.
- 가능하면 "-ing" 단어를 피한다.

## 두 가지로 읽히는 문장을 남기지 않는다 (Global English)

- "only"와 "not" 같은 단어는 꾸미는 단어 바로 옆에 둔다.
- 긴 명사 나열을 끊는다.
- "it", "they", "this"는 분명한 대상 하나를 가리키게 한다. "this"나 "which"로 절 전체를 가리키지 않는다.
- 동사나 구조를 드러내는 작은 단어("that" 같은)를 빼지 않는다.
- 오독을 막을 때는 나열에서 관사를 반복한다. "and"나 "or"가 무엇을 잇는지 밝힌다.
- 세미콜론이나 em dash가 아니라 마침표를 쓴다. 슬래시와 "(s)"를 쓰지 않는다. 괄호 안 글은 문법적으로 온전한 단위로 만든다.
- 한 대상은 어디서나 이름 하나로 부른다.
- 관용구, 구어, 라틴어 약어, 은유를 쓰지 않는다.

## 어조와 저장소별 사항

- 이 스킬이 다루는 모든 문서에 **unslop**을 적용한다. AI 어휘, 군더더기, 얼버무림, 서식 티 같은 슬롭 패턴 목록은 그 스킬이 소유한다.
- PR 본문과 커밋 메시지도 글이다. Diátaxis를 뺀 모든 층이 적용된다. PR 본문은 리뷰어가 1분 안에 읽는 브리핑이다. swarm 로그, SHA 목록, 지표 표를 붙이지 않는다. 링크한다.
- 제품 UI 문구는 문서가 아니다. 그건 제품의 카피 가이드를 따른다.
- 코드 조각은 탭으로 들여 쓴다. 실제 경로를 쓴다. 개수나 트리 주장은 그것을 넣는 커밋 시점에 참이게 하고, 다시 만들어 내는 명령을 함께 적는다.
