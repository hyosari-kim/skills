# Smallest Change

**언제:** diff 크기를 정할 때, 추상화·레이어·옵션을 추가하고 싶을 때, 같은 판단이 여러 곳에 생기려 할 때.

**규칙:** 문제를 푸는 가장 작은 변경을 택한다. 더하기 전에 뺀다.

**한다**
- 쌓기 전에 먼저 지운다. 죽은 코드, 호출처가 하나뿐인 래퍼, 중복 검증, 내용 없는 참조를 정리한 뒤 그 위에 만든다.
- 같은 판단은 한 곳에 둔다. 여러 곳에서 같은 조건을 다시 계산하지 말고, 한 곳에서 정한 결과를 넘긴다. 넘길 때는 단순한 플래그 하나로 넘긴다.
- 실제로 관찰된 사용 방식에 맞춘다. 요구에 없는 검증, 파서, 방어 코드는 넣지 않는다.
- 최소한으로 동작하게 만든 다음에 다듬는다.
- 변경이 끝나면 표면(공개 API, 옵션, 파일 수)이 같거나 줄어 있어야 한다.

**신호(멈추고 다시 본다)**
- "나중에 필요할 수도 있어서" 넣는 매개변수나 확장 지점.
- 한 줄 신호를 전달하려고 여러 컴포넌트에 값을 꿰는 변경.
- 짧게 쓸 수 있는데 "깔끔해 보여서" 늘어난 보일러플레이트.
- 지워도 아무것도 안 깨지는 코드를 남겨둔 채 새 코드를 얹는 것.
