# Fix Root Causes

**언제:** 디버깅할 때. 증상을 막는 수정을 넣고 싶을 때.

**규칙:** 증상이 드러난 곳이 아니라 원인을 고친다. 근본 원인은 시스템이 처음으로 하지 말아야 할 일을 했거나, 처리했어야 할 상태를 처리하지 못한 지점이다.

**한다**
- 바꾸기 전에 재현한다.
- 답이 코드 속 특정한 잘못된 판단이 될 때까지 "왜"를 계속 묻는다.
- 막히면 계측을 넣고 실제 상태를 읽는다. 추측으로 메우지 않는다.
- 문제를 일으킨 상태가 정상인지 묻는다.
  - 정상 상태라면, 코드가 깨진 그 지점에서 처리한다.
  - 있어서는 안 되는 상태라면, 그 상태를 만든 곳을 찾는다. 증상 지점의 검사는 버그를 숨길 뿐이다.
- 같은 결함이 있는 다른 곳도 찾아서 패턴째 고친다.
- 핵심 사실을 찾는 데 오래 걸렸다면, 다음엔 바로 보이게 할 싼 상시 신호(로그, assert, 에러 메시지)를 제안한다.

**버그를 숨기는 흔한 방법(하지 않는다)**
- 비정상 상태에 방어 코드를 붙이고 원인은 그대로 두기.
- 실패를 가리는 재시도.
- 삼킨 예외.
- 범위를 벗어난 값을 조용히 잘라내기.
- 무엇이 잘못됐는지 보여줄 상태를 버리기.
