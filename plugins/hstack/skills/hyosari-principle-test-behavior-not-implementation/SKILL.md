# Test Behavior, Not Implementation

테스트는 코드를 쓰는 쪽이 인터페이스를 통해 관찰할 수 있는 것에 대한 주장이다. 반환값, 오류, 다시 읽을 수 있는 상태, 외부 시스템에 미치는 효과. 비공개 헬퍼, 내부 호출 순서, 중간 데이터는 구현이다.

각 테스트를 상상한 수정 두 가지에 대어 본다.

- **동작을 깨뜨린다**(틀린 값, 빠지거나 두 번 일어난 효과). 테스트가 여전히 통과하면 아무것도 증명하지 못한다. 흔한 원인은 느슨한 단언, 테스트 대상 코드로 계산한 기대값, 테스트가 직접 만든 데이터에 대한 단언이다.
- **내부를 바꾸고** 관찰 가능한 결과는 모두 유지한다. 테스트가 실패하면 구현에 묶여 있는 것이다.

첫 번째 수정을 잡고 두 번째 수정에서 살아남는 테스트를 남긴다. 나머지는 다시 쓰거나 지운다. 구체적인 입력으로 공개 인터페이스를 통해 코드를 움직이고, 기대값은 요구사항에서 끌어낸다. 외부 서비스가 받는 것은 동작이다. 내부 헬퍼 호출은 동작이 아니다. "이런 일은 절대 없다"는 테스트에는 그 일이 실제로 일어나는 경우를 짝지어 둔다. 메시지가 아니라 호출하는 쪽이 분기하는 오류 타입을 확인한다.
