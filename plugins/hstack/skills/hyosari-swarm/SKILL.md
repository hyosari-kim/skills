# Hyosari swarm

## Start

무엇이든 띄우기 전에 단계마다 한 항목씩 할 일 목록을 연다.

1. Frame
2. Fan out
3. Aggregate
4. Report

## Phase A: Frame

1. 완료 조건(done predicate)과 swarm이 돌려줘야 할 산출물이나 보고서를 적는다.
2. 모양을 고른다. 작업을 조각으로 나누거나, 같은 브리프로 워커 N개를 경주시키거나, 둘을 섞는다. 경주나 섞은 모양이면 띄우기 전에 선택 규칙을 `first pass`, `rank all`, `best-of` 중에서 선언한다.
3. 워커 모델을 고른다. 기본은 `model: "opus", effort: "high"`다. `Agent` 도구가 값을 거부하면 스키마가 받는 가장 가까운 값을 쓰고 그렇게 했다고 말한다. 모델 경주라면 각 갈래의 모델을 미리 적는다. 서브에이전트마다 추론 수준(`effort`)은 일에 맞게 **hyosari-mode** 스킬의 Subagents 섹션을 따라 고른다.
4. 쓰는 워커에게는 각자 쓸 수 있는 출력 위치를 준다. 워커가 커밋을 검증하거나 측정하면 브리프마다 정확한 SHA를 적는다. 측정 브리프에는 방법(샘플 수, 샘플 하나가 무엇인지, 순서)도 적는다. 워커는 결과에 둘 다 기록한다.

## Phase B: Fan out

워커 N개를 `Agent` 호출로 한 메시지에 모두 띄운다. `subagent_type: "general-purpose"`, `isolation: "worktree"`, 3단계에서 고른 `model`과 `effort`를 준다. 워커가 사용자 컴퓨터의 지금 작업 디렉터리에 있는 것(커밋하지 않은 변경 등)이 필요할 때만 `isolation`을 뺀다.

워커는 worktree에서 브랜치나 커밋을 체크아웃하고 시작한다. 브리프에 그 브랜치나 커밋을 적는다. 기본이 아닌 push된 브랜치에서 시작해야 하면 그 브랜치를 먼저 체크아웃하라고 브리프에 쓴다.

브리프는 각자 혼자 읽어도 되게 쓴다. 목표, 범위, 정확한 조각이나 경주 갈래, 검증 방법, 보고할 것을 넣는다. 보고는 증거와 함께 `PASS`, `ISSUES`, `BLOCKED` 중 하나로 한다. 결함을 증명할 수 있는 워커는 `ISSUES`로 보고하고, 첫 번째만이 아니라 증명할 수 있는 이슈를 모두 적는다.

워커 하나가 빠지면 N-1개로 진행하고 그렇다고 적는다.

## Phase C: Aggregate

워커의 최종 결과를 읽는다. 브리프가 정한 SHA와 방법을 기록하지 않은 결과는 버리고, 그 워커를 한 번 다시 띄운다. 두 번째에도 빠지면 공백으로 기록한다. 공백은 통과로 치지 않는다. 커버리지라면 필요한 조각마다 결과가 있어야 한다. 경주라면 미리 선언한 선택 규칙(first pass, rank all, best-of)을 적용한다. 워커 출력을 날것 그대로 붙이지 않는다.

## Phase D: Report

대화 안에 통합 보고서 하나를 돌려준다. 결과 표, 이슈 한 줄 요약, 공백이나 빠진 워커, 경주였다면 그 선택 규칙을 넣는다.
