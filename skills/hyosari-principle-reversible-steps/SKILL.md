# Reversible Steps

**언제:** 데이터 변경, 스키마 변경, 백필, 마이그레이션, 배포. 비슷한 수정을 여러 곳에 반복하는 일. 커밋과 PR을 쌓는 순서를 정할 때.

**규칙:** 되돌릴 방법이 있는 작은 단위로 나누고, 각 단위는 확인 가능한 상태로 끝낸다. 지금 단위가 통과하기 전에는 다음으로 넘어가지 않는다.

**한다**
- 시작 전에 되돌리는 방법과 기존 데이터에 미치는 영향을 먼저 적는다. 되돌릴 수 없으면 멈추고 사용자에게 확인한다.
- 단위마다 같은 틀을 쓴다. 정상인 시작 상태 확인 → 변경 하나 → 확인 실행 → 통과하면 다음.
- 도구가 대신 수정했어도 단위별 확인은 건너뛰지 않는다.
- 상태를 바꾸는 작업은 여러 번 돌려도, 중간에 죽었다가 다시 돌려도 같은 결과가 나오게 만든다.
  - 지난 실행이 하려던 것이 아니라 지금 상태를 읽고, 목표와의 차이만 적용한다.
  - 임시 경로에 쓰고 rename으로 교체한다.
  - 잠금, 임시 파일, 반쯤 쓴 레코드는 오래된 것인지 판별할 수 있게 남긴다.
  - "두 번 돌리면?", "아무 지점에서나 죽었다면?" 두 질문으로 점검한다.
- 리뷰어가 순서만 봐도 증명이 되게 쌓는다. 실패하는 테스트 → 수정, 삭제 → 재구성, 기준 측정 → 변경. 커밋 하나하나가 그 자체로 통과 상태여야 한다.

**신호**
- 여러 곳을 한 번에 바꾸고 마지막에 한 번만 확인하려 한다.
- 되돌리려면 손으로 데이터를 고쳐야 한다.
- 재실행 결과가 지난 실행이 어디서 멈췄는지에 따라 달라진다.
