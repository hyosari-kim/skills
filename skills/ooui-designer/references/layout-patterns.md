# Step 3. 프레젠테이션: 레이아웃 패턴

## 목차
- 원칙
- 선택 절차 (명백한 결정 / 옵션 제안)
- A. 루트 네비게이션 배치
- B. 뷰 연결 방식
- C. 컬렉션 형식
- D. 필터링과 정리
- E. 싱글 표시
- F. 생성 (Create)
- G. 수정 (Update)
- H. 삭제 (Delete)

- J. 모바일 관용구 대응표
- 결정 기록 형식

## 원칙
- 목록, 상세, 생성, 편집, 삭제에는 경험적으로 검증된 좋은 패턴이 이미 있다. **이미 사용자에게 익숙한 패턴에서 고른다.** 새 패턴은 기존 패턴으로 요구를 풀 수 없을 때만 만든다.
- **같은 모델, 다른 배치.** 화면 크기가 달라도 모델과 뷰는 그대로 두고, 뷰를 한 화면에 나란히 둘지(넓은 화면) 화면 전환으로 나눌지(좁은 화면)만 바꾼다.
- 모든 결정에는 "패턴 + 이유" 한 줄을 남긴다.

## 선택 절차

레이아웃 패턴은 같은 모델에서도 여러 개가 타당할 수 있고, 어떤 것을 고르느냐에 따라 앱의 성격이 달라진다. 그래서 명백한 결정만 에이전트가 정하고, 나머지는 사용자에게 옵션을 제시해 고르게 한다.

### 1. 결정마다 명백한지 판정한다

**기본값**

| 결정 | 기본값 |
|---|---|
| 모바일 루트 네비게이션 | 하단 탭 3~5개, 메인 객체 컬렉션만. 계정·설정은 탭 밖 |
| 컬렉션 → 싱글 연결 | 좁은 화면은 화면 전환, 넓은 화면은 좌우 분할 |
| 컬렉션 형식 | 사용자가 항목을 알아보는 속성으로: 날짜 → 캘린더, 이미지 → 그리드, 위치 → 맵, 상태 → 보드, 텍스트 → 리스트 |
| 필터·검색 | 컬렉션의 상태로 둔다. 별도 검색 화면을 만들지 않는다 |
| 생성 | 필수 속성 1~2개면 블랭크, 그 이상이거나 검증이 필요하면 파라미터 |
| 수정 | 모드리스 에디트 + 자동 저장 |
| 삭제 | 즉시 삭제 + 되돌리기. 되돌릴 수 없고 영향이 크면 모달 확인 |

**명백함 → 바로 정하고 이유를 적는다**
- 위 기본값에 해당하고, 모델에 반대 근거가 없다
- 플랫폼 관용구로 사실상 하나로 정해진다 (모바일 전용 앱의 루트 = 하단 탭, 좁은 화면의 컬렉션 → 싱글 = 화면 전환)
- 모델에서 결정적인 근거가 나온다 (★핵심 속성이 날짜뿐 → 캘린더)
- 사용자가 이미 지정했거나 스케치에 그려두었다

**명백하지 않음 → 옵션으로 제안한다**
- 두 개 이상의 패턴이 모두 모델에서 근거를 가진다 (★핵심 속성이 날짜와 제목 둘 → 캘린더 vs 리스트, C1 vs C2)
- 선택에 따라 사용 경험의 성격이 달라진다 (모드리스 vs 모달 에디트, 되돌리기 vs 모달 확인, 화면 전환 vs 좌우 분할)
- 기본값과 모델의 신호가 충돌한다 (필수 속성은 하나지만 검증이 필요하다 → 블랭크 vs 파라미터)
- 앱의 정체성에 영향을 준다. 특히 메인 객체의 컬렉션 형식은 앱의 성격을 결정하므로, 조금이라도 후보가 둘이면 제안한다
- 되돌리기 비용이 크다 (루트 네비게이션 구성, 탭 순서)

### 2. 애매한 결정을 모아 한 번에 제시한다

- 결정 하나마다 묻지 말고, Step 3의 애매한 결정을 모아 **한 번의 "레이아웃 선택 요청"**으로 제시한다.
- 5개를 넘으면 영향이 큰 순서(루트 네비게이션 → 메인 객체 컬렉션 형식 → 뷰 연결 → 싱글 표시 → CRUD 패턴)로 3~5개만 묻고, 나머지는 추천안을 적용해 `(가정: 추천안)`으로 표시한다.
- 선택 요청 앞에는 Step 1~2의 결과(객체 표와 뷰 목록)를 짧게 보여줘서, 사용자가 무엇에 대한 선택인지 알 수 있게 한다.
- 사용자에게 선택지를 버튼으로 보여주는 도구가 있으면 그것을 쓴다. 질문 하나에 옵션은 2~4개로 한다.

### 3. 옵션 제시 형식

```markdown
### 레이아웃 선택 요청

**1. 안건 [C]의 컬렉션 형식**
| 옵션 | 모습 | 장점 | 비용 |
|---|---|---|---|
| A. 1항목 여러 행 + 월별 섹션 (추천) | 내용 두 줄 미리보기, 월 헤더로 묶음 | 내용으로 알아보기 쉽다. 이번 달 확인이 한눈에 | 오래된 항목은 스크롤이 길다 |
| B. 보드 (미해결 / 해결됨) | 상태별 두 열 | 해결 흐름이 시각적으로 보인다 | 모바일에서 폭이 좁고, 월별 확인이 어렵다 |
추천 이유: ★핵심 속성이 내용과 작성일이고 "이번 달 안건 확인" 태스크를 직접 지원한다.

**2. ...**

응답이 없으면 추천안으로 진행합니다.
```

- 각 옵션은 카탈로그의 패턴 이름과 ID로 부른다.
- **추천안은 반드시 하나 표시**하고, 모델(★속성, 관계, 태스크)에 근거한 이유를 한 줄로 적는다.
- 옵션 수는 2~3개. 명백히 나쁜 옵션을 끼워 넣어 개수를 채우지 않는다.

### 4. 선택 후
- 사용자가 고른 결정은 결정 기록의 "결정 방식"에 `사용자 선택`으로 적는다.
- 선택 결과 때문에 모델이나 뷰를 바꿔야 하면(예: 보드를 골라 상태 속성이 중요해짐) Step 1~2로 돌아가 반영한 뒤 산출물을 마무리한다.

## A. 루트 네비게이션 배치

| 패턴 | 적합한 경우 | 주의 |
|---|---|---|
| 하단 탭바 | 모바일, 메인 객체 3~5개 | 아이콘 + 명사 라벨. 아이콘만 두지 않는다 |
| 상단 탭·바 | 웹·데스크톱, 메인 객체가 적을 때 | |
| 좌측 사이드바 | 메인 객체가 많은 업무용 앱 | 단서 객체(폴더 등) 목록을 함께 두기 좋다 |
| 개폐식 드로어 | 좁은 화면에서 객체가 6개 이상일 때 | 발견성이 낮다. 핵심 객체는 탭에 두고 드로어는 보조로만 |

## B. 뷰 연결 방식

| 패턴 | 적합한 경우 | 주의 |
|---|---|---|
| 화면 전환 (드릴다운, push) | 좁은 화면의 기본값 | 계층이 모델 관계를 반영하게 한다 |
| 좌우 분할 (마스터-디테일) | 넓은 화면에서 항목을 차례로 훑으며 비교할 때 (C3) | 좁아지면 같은 순서의 화면 전환으로 바뀐다 |
| 다른 객체 병치 | 왼쪽 컬렉션의 항목으로 오른쪽 싱글을 조립할 때 (C4) | 좁은 화면에서는 싱글을 하단 시트나 요약 바로 줄여 계속 보이게 한다 |
| 3단 분할 | 단서 객체 → 컬렉션 → 싱글 (메일형) | 가장 넓은 화면에서만 |
| 시트·팝오버 | 짧은 확인, 빠른 미리보기, 파라미터 생성 폼 | 핵심 싱글을 시트에 가두지 않는다 |
| 인라인 펼침 | 속성이 적은 싱글 | 펼친 상태에서도 제자리 편집이 되게 한다 |

## C. 컬렉션 형식

컬렉션의 형식이 앱의 성격을 결정한다. 사용자는 컬렉션 형식을 보고 이미 아는 관용구와 비교하며 앱을 이해한다. **사용자가 항목을 무엇으로 알아보고 찾는지**(★ 핵심 속성)를 기준으로 고른다.

| 형식 | 기준이 되는 속성 | 예 |
|---|---|---|
| 1항목 1행 리스트 | 이름이나 짧은 값 | 사람, 태그, 설정 항목, 업무 목록 |
| 1항목 여러 행 리스트 | 제목 + 본문 미리보기 | 메시지, 메모, 글 |
| 썸네일 그리드 | 이미지 | 사진, 상품, 책 표지 |
| 테이블 | 여러 속성의 비교·정렬 | 데스크톱 업무 앱 |
| 캘린더 | 날짜 | 일정, 일지, 습관 기록 |
| 타임라인·간트 | 기간, 순서 | 프로젝트, 이벤트 |
| 맵 | 위치 | 매장, 장소 |
| 보드 (칸반) | 상태 | 작업, 파이프라인 |

- 한 객체에 형식 전환(리스트 ↔ 캘린더)을 둘 수 있다 (V2).
- 형식 안의 객체 표현(카드, 막대, 핀)을 직접 조작할 수 있으면 더 좋다 (드래그로 날짜 변경, 순서 변경).

## D. 필터링과 정리

| 패턴 | 쓰임 |
|---|---|
| 키워드 검색 | 빠르게 찾기 |
| 조건 필터 (AND, 패싯) | 복잡한 조건 |
| 세그먼트 (상태별 탭) | 상태 속성이 2~4개 값일 때 (미해결 / 해결됨) |
| 그룹핑 (섹션 헤더) | 월별, 상태별로 묶어 보기 |
| 정렬 | 필터는 아니지만 정보를 정리한다 |

- 기본값: 최신순 + 필요할 때 검색. 다른 정렬·그룹은 옵션으로 둔다.
- 필터는 컬렉션의 상태다. 별도 "검색 화면"을 만들지 않는다 (V3).

## E. 싱글 표시

| 패턴 | 적합한 경우 |
|---|---|
| 싱글 메인 (C2) | 자기 속성이 중요하다. 속성이 본문이고, 관련 컬렉션은 일부만 보여주고 "모두 보기"로 넘긴다 |
| 컬렉션 메인 (C1) | 단서·그릇 객체. 자기 속성은 헤더에 요약하고, 자식 컬렉션이 본문이다 |
| 면 분할 싱글 | 속성이 많다. 탭이나 세그먼트로 나누되 하나의 싱글이다 (M2) |

## F. 생성 (Create)

| 패턴 | 동작 | 적합한 경우 |
|---|---|---|
| 블랭크 | "추가"를 누르면 빈 항목이 컬렉션에 바로 생기고 그 자리에서 입력한다 | 필수 속성 1~2개, 빠른 연속 입력 |
| 파라미터 | 폼(시트나 새 화면)에 입력한 뒤 등록한다 | 필수 속성이 많거나 검증이 필요하다 |
| 복제 | 기존 객체를 복사한 뒤 수정한다 | 비슷한 객체를 반복해서 만든다 |
| 기본값 즉시 생성 | 기본값으로 바로 만들고 싱글을 연다 | 날짜 단위 기록처럼 기본값이 명확하다 |

생성은 컬렉션의 액션이다. 생성한 뒤에는 N5를 따른다.

## G. 수정 (Update)

| 패턴 | 동작 | 적합한 경우 |
|---|---|---|
| 모드리스 에디트 (기본값) | 항상 편집 가능하고 자동 저장된다. 저장 버튼이 없다 | 대부분 |
| 모달 에디트 | 보기/편집 모드를 전환하고 저장·취소한다 | 여러 필드를 한 번에 확정해야 할 때, 편집 중 상태가 노출되면 안 될 때, 승인이 필요할 때, 편집 자체가 다른 조작 방식을 요구할 때 |

## H. 삭제 (Delete)

| 패턴 | 동작 | 적합한 경우 |
|---|---|---|
| 되돌리기 (기본값) | 즉시 삭제하고 토스트로 되돌리기를 제공한다 | 대부분. 모드리스 원칙에 가장 잘 맞는다 |
| 모드리스 확인 | 삭제를 누르면 그 자리에 확인 버튼이 나타난다 | 되돌리기 구현이 어렵고 영향이 작을 때 |
| 모달 확인 | 확인 다이얼로그 | 되돌릴 수 없고, 다른 객체에 영향이 클 때. 영향 범위를 문구로 알려준다 |

## I. 액션 배치

| 액션 | 위치 |
|---|---|
| 싱글 액션 | 싱글의 헤더·툴바 또는 하단 액션바. 주요 액션 1개를 강조한다 |
| 컬렉션 액션 | 컬렉션 헤더 (추가, 정렬, 필터) |
| 항목 빠른 액션 | 스와이프, 롱프레스, 컨텍스트 메뉴. **보조 경로일 뿐이고 같은 액션이 싱글에도 있어야 한다** |
| 다중 선택 액션 | 컬렉션의 일시적인 선택 상태에서만 나타난다 (아래 다중 선택 패턴) |

- 생성 액션은 아직 존재하지 않는 항목을 만드는 것이므로 컬렉션에만 둔다. 그 밖의 액션은 기본적으로 컬렉션 항목과 싱글 양쪽에 있을 수 있다.

**다중 선택 패턴.** 컬렉션 항목의 탭은 보통 "싱글 열기"라서, 여러 개를 고르는 탭과 충돌한다.

| 패턴 | 동작 | 적합한 경우 |
|---|---|---|
| 선택 모드 | "선택" 버튼이나 롱프레스로 모드에 들어가고, 모드 안에서는 탭 = 선택 | 다중 선택이 가끔 필요하다 |
| 상시 선택 | 항목에 두 영역을 둔다. 본문 탭 = 싱글 열기, 체크박스 탭 = 선택 | 다중 선택이 자주 필요하다. 모드리스하다 |
| 싱글 없는 선택 | 싱글을 생략한 컬렉션(O3)에서는 탭 = 선택으로 쓴다 | 컬렉션만으로 충분하다 |
| 장바구니형 객체 | 고른 항목을 별도 객체(장바구니)에 담는다 (C4) | 항목이 많고, 고른 것들을 따로 확인·수정해야 한다 |

- 좌우 분할에서 "항목을 열면 자동으로 선택까지 되는" 동작은 피한다. 구경하려고 연 항목이 계속 선택되어 해제하는 수고가 생긴다.
- 다중 선택이 복잡해진다면 연속 작업(N6)으로 대체할 수 있는지 먼저 검토한다. 액션 후 컬렉션에 머물게 하면 한 번에 여러 개를 고르지 않아도 부담이 크게 줄어든다.

## J. 모바일 관용구 대응표 (iOS · Android)

| OOUI 요소 | 모바일 구현 |
|---|---|
| 루트 네비게이션 | 하단 탭 바 |
| 컬렉션 → 싱글 | 스택 push |

## 결정 기록 형식

| 대상 | 결정 | 패턴 | 이유 | 결정 방식 |
|---|---|---|---|---|
| 루트 네비게이션 | 하단 탭 4개 | A. 하단 탭바 | 모바일 전용, 메인 객체 4개 | 명백 |
| 회의 [C] | 월 캘린더 | C. 캘린더 | ★날짜로 찾는다 | 명백 |
| 안건 [C] | 1항목 여러 행 + 월별 섹션 | C, D. 그룹핑 | 내용으로 알아보고, 이번 달 확인 | 사용자 선택 |
| 결정사항 생성 | 블랭크 | F. 블랭크 | 필수 속성이 내용 하나 | (가정: 추천안) |

결정 방식은 `명백` / `사용자 선택` / `(가정: 추천안)` 중 하나다.
