# 검증과 리뷰

두 가지 용도로 쓴다. (1) 내가 만든 설계를 Step 4에서 검증할 때, (2) 사용자의 기존 UI, 스케치, 와이어프레임을 리뷰할 때.

## 1. 태스크 커버리지 검증 (Step 4)

모든 태스크를 다음 형식으로 적는다.

| 태스크 | 경로 (객체 선택 → 액션) | 탭·조작 수 | 판정 |
|---|---|---|---|
| 안건이 해결되면 결정사항을 적는다 | 안건 [C] → 항목 [S] → "해결됨" → 결정사항 입력 | 3 | ✅ |

- 경로가 "객체 → 액션" 형태로 쓰이지 않으면 모델에 객체나 액션이 빠진 것이다. Step 1로 돌아간다.
- 같은 목적에 경로가 두 개 이상이면 둘 다 같은 객체와 액션을 쓰는지 확인한다. 서로 다른 화면이 같은 일을 하면 중복이다.
- 예외 흐름으로만 달성되는 태스크가 있으면 흐름 밖 경로를 추가한다 (principles.md §3 규칙 4).
- 조작 수가 유난히 많은 태스크는 루트 네비게이션 순서나 N2(부모 싱글 안 자식 컬렉션)를 다시 검토한다.

## 2. 설계 체크리스트

**모델**
- [ ] 모든 객체가 판정 테스트를 통과했다 (또는 싱글톤이라는 근거가 있다)
- [ ] 객체 이름이 사용자의 도메인 언어다
- [ ] 명사화된 동사("해결", "공유")를 객체로 잘못 만들지 않았다
- [ ] 모든 액션 이름을 "[객체]의 [X]를 [동사]"로 풀어 써서 숨은 속성·객체를 확인했다 (AO1)
- [ ] 특정 액션을 거쳐야만 보이는 객체가 없다 (AO3)
- [ ] 결과를 얻으려고 실행하는 액션(계산, 조회) 대신 결과를 속성으로 보여줄 수 있는지 검토했다 (AO5)
- [ ] 기록으로 남는 행위(신청, 예약, 주문)를 객체 후보로 올려 판정 테스트를 거쳤다 (AO6)
- [ ] 관계와 다중도, 소유/참조 구분이 모두 적혀 있다
- [ ] DB 전용 구조(조인 테이블, 로그)가 섞이지 않았다

**뷰와 네비게이션**
- [ ] 메인 객체마다 컬렉션과 싱글이 있거나, 생략 ID(O1~O5)와 이유가 적혀 있다
- [ ] 결합(C1~C6)과 싱글 분리(M1~M2)에 ID와 이유가 적혀 있다
- [ ] 한쪽 객체를 보려고 다른 쪽을 떠나야 하는 곳이 없다. 있다면 C4·C6 결합을 검토했다
- [ ] 태스크 선택(사기/팔기 등)으로 나뉜 화면을 두 객체의 컬렉션으로 바꿀 수 있는지 검토했다 (C6)
- [ ] 루트 네비게이션이 메인 객체 컬렉션만으로 구성되고 라벨이 모두 명사다
- [ ] 앱 실행 직후 메인 객체가 보인다 (P2)
- [ ] 모든 1:N 관계가 부모 싱글 안의 자식 컬렉션으로 나타난다 (N2)
- [ ] 검색·필터가 별도 화면이 아니다 (V3)
- [ ] 예외 흐름에는 허용 조건 ID와 객체 입구·출구가 있다

**레이아웃과 액션**
- [ ] 모든 액션이 대상이 정해진 상태에서 나타난다 (P1)
- [ ] 상태가 객체 표현 자체에 드러난다 (P3)
- [ ] 수정은 기본적으로 모드리스이고, 모달 에디트에는 근거가 있다
- [ ] 삭제는 기본적으로 되돌리기이고, 모달 확인에는 근거가 있다
- [ ] 제스처 전용 액션이 없다 (싱글에도 같은 액션이 있다)
- [ ] 같은 객체가 모든 뷰에서 같은 모양과 이름이다 (P5)
- [ ] 결정마다 패턴과 이유가 기록되어 있다
- [ ] 명백하지 않은 결정은 사용자가 골랐거나 `(가정: 추천안)`으로 표시되어 있다
- [ ] 선택 결과가 모델·뷰에 영향을 주는 경우 Step 1~2에 반영했다

## 3. 기존 UI 리뷰 절차

1. **화면 목록 만들기:** 모든 화면과 메뉴 라벨을 나열한다.
2. **라벨 분류:** 각 라벨을 명사/동사로 분류한다. 동사 라벨, 명사·동사 혼재는 `principles.md` §4 신호로 기록한다.
3. **중복 목록 찾기:** 비슷한 목록 화면이 여러 태스크에 반복되는지 찾는다. 그 목록의 항목이 누락된 객체다.
4. **객체 추출:** 화면에 쓰인 명사와 입출력 정보에서 객체를 뽑는다 (`modeling.md`의 "암묵적 객체 찾기").
5. **액션 다시 읽기:** 이미 객체 → 액션 순서로 된 화면이라도 모든 액션 라벨에 AO1~AO6을 적용해 숨은 속성과 객체를 꺼낸다.
6. **개선 모델 제시:** Step 1~3을 적용해 객체 기반 구조를 제시한다.
7. **비교표 작성:** 전후의 화면 수, 대표 태스크의 조작 수, 루트 네비게이션 라벨을 비교한다.

리뷰 결과는 이 형식으로 적는다.

## 4. 태스크 → 객체 전환 요령

- 동사 메뉴의 목적어가 객체다. "사진 편집" → 사진 [C] → 사진 [S]의 "편집" 액션
- 위저드의 단계들은 대부분 싱글의 속성 입력으로 합쳐진다
- "현황", "대시보드" 화면은 상태 속성(◆)을 컬렉션 항목에 드러내면 대부분 필요 없어진다
- "~관리" 화면은 대개 그 객체의 컬렉션 + 싱글 액션으로 바뀐다
