# Follow the Codebase

**언제:** 새 패턴, 라이브러리, 도구, 파일 구조를 들이고 싶을 때. 처음 보는 스택의 코드를 다룰 때.

**규칙:** 기존 컨벤션이 이미 푸는 문제인지 먼저 본다. 푼다면 따른다. 내 취향이 더 낫다는 것은 새 방식을 들일 이유가 아니다.

**한다**
- 이 순서로 기준을 찾는다. 그 스택용 스킬 → 프로젝트 `CLAUDE.md`·`AGENTS.md` → 같은 저장소의 비슷한 구현.
- 비슷한 기능이 어떻게 만들어졌는지 하나 이상 찾아 읽고, 이름, 파일 위치, 에러 처리, 테스트 방식을 맞춘다.
- 이미 있는 유틸리티와 헬퍼를 먼저 찾아 쓴다. 비슷한 것을 새로 만들지 않는다.
- 기존 컨벤션이 정말 문제라고 판단하면 몰래 바꾸지 않는다. 문제와 대안을 사용자에게 말하고 이번 변경과 분리한다.

**신호**
- 저장소에 없던 의존성이나 빌드 도구를 추가하려 한다.
- 같은 일을 하는 두 번째 방식이 저장소에 생긴다.
- 주변 코드와 이름 짓는 방식이나 파일 배치가 다르다.
